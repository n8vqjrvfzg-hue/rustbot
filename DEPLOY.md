# Запуск бота на сервере (VPS)

> Для Beget есть отдельная пошаговая инструкция: **DEPLOY_BEGET.md** (с автоматическим скриптом установки и командой `botctl`).

Бот работает как обычная программа, ему нужен сервер, который включён 24/7. Самый простой вариант — арендованный VPS с Linux.

## 1. Что взять
- **VPS**: 1 vCPU, 1 ГБ RAM, 10 ГБ диска. Для сообщества до нескольких тысяч человек хватает с запасом.
- **ОС**: Ubuntu 24.04 (в ней уже есть Python 3.12 — это то, что нужно).
- Где: Hetzner (Германия, ~4 €/мес), Timeweb Cloud, Selectel, Aeza и др. Бот ходит к Telegram сам, открытые порты и домен **не нужны**.
- После покупки вам пришлют **IP-адрес** и пароль (или попросят добавить SSH-ключ).

## 2. Подключиться к серверу
- **С ПК (Windows)**: открой PowerShell и введи `ssh root@IP_СЕРВЕРА`.
- **С телефона**: приложение **Termius** (Android/iOS) — добавь хост, логин и пароль/ключ. В нём же есть SFTP для загрузки файлов.

## 3. Подготовить сервер (один раз)
```bash
apt update && apt upgrade -y
apt install -y python3 python3-venv python3-pip unzip ufw
adduser --disabled-password --gecos "" bot        # отдельный пользователь для бота
ufw allow OpenSSH && ufw --force enable           # фаервол: открыт только SSH
```

## 4. Загрузить бота
**С ПК** (PowerShell, из папки с архивом):
```powershell
scp rustbot_stage8.zip root@IP_СЕРВЕРА:/tmp/
```
(с телефона — загрузи архив через SFTP в Termius в папку /tmp)

**На сервере:**
```bash
cd /opt && unzip -o /tmp/rustbot_stage8.zip
cd /opt/rustbot
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
cp .env.example .env && nano .env        # заполни значения, Ctrl+O, Enter, Ctrl+X
chmod 600 .env
chown -R bot:bot /opt/rustbot
```

Проверь запуск вручную: `sudo -u bot /opt/rustbot/venv/bin/python main.py`. Если в консоли появилось «Бот @... запущен» — напиши боту /start, затем останови его через Ctrl+C.

> ⚠️ Токен можно использовать **только в одном месте**. Перед запуском на сервере останови бота на своём ПК, иначе будет ошибка «Conflict: terminated by other getUpdates request».

## 5. Автозапуск и перезапуск при сбоях
```bash
cp /opt/rustbot/deploy/rustbot.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now rustbot
```
Теперь бот стартует вместе с сервером и сам перезапускается через 5 секунд после падения.

## 6. Повседневное управление
| Что сделать | Команда на сервере |
|---|---|
| Статус | `systemctl status rustbot` |
| Логи в реальном времени | `journalctl -u rustbot -f` |
| Файл логов бота | `/opt/rustbot/logs/bot.log` |
| Перезапустить | `systemctl restart rustbot` |
| Остановить / запустить | `systemctl stop rustbot` / `systemctl start rustbot` |
| Обновить версию | загрузить новый архив (шаг 4, `unzip -o`), затем `sudo bash /opt/rustbot/deploy/update.sh` |

Обновление **не затрагивает** `.env`, базу `bot.db` и `venv`: в архиве их нет.

## 7. Управление с телефона и ПК
- **Сам бот**: админ-меню, настройки, режим тех. работ, экстренный сбор — всё в Telegram.
- **/status** (заместитель и выше) — аптайм, размер базы, количество участников, очередь анкет.
- **/backup** и **/export** (владелец) — бот присылает копию базы и выгрузку таблиц в CSV прямо в чат.
- **SSH** (Termius на телефоне / PowerShell на ПК) — логи, перезапуск, обновление.
- **Файлы**: Termius SFTP (телефон) или WinSCP / FileZilla (ПК).

## 8. Сохранность данных и резервные копии
Данные участников (профили, репутация, статистика админов, анкеты) лежат в файле `bot.db`. Защита устроена в несколько уровней:

1. **Запись на диск при каждом действии.** Каждое изменение сразу фиксируется (режим WAL + `synchronous=FULL`). Если бот или сервер внезапно выключится, потеряется максимум действие, которое выполнялось в эту долю секунды. Мы проверяли: процесс «убивали» посреди записи — все подтверждённые записи были на месте, а база осталась целой.
2. **Корректная остановка.** При `systemctl stop/restart` бот закрывает базу и сводит журнал в основной файл.
3. **Копии на сервере.** Каждые 24 часа (`BACKUP_EVERY_HOURS`) бот проверяет целостность базы и сохраняет копию в `/opt/rustbot/backups/` (последние 14).
4. **Копии ВНЕ сервера — в Telegram.** Те же копии бот присылает в чат: по умолчанию в личку первого владельца, либо в чат/канал из `BACKUP_CHAT_ID` (лучше закрытый). Приходят два файла: `bot_….db` (вся база) и `export_….zip` (все таблицы в CSV — открывается в Excel и Google Таблицах, там удобно смотреть статистику участников и админов). Если сервер пропадёт совсем, копия останется в твоём Telegram.
5. **По запросу.** `/backup` — свежая копия базы, `/export` — выгрузка в CSV (только владелец).
6. **Снимки у хостера.** Включи автоматические бэкапы/снапшоты сервера в панели провайдера (обычно +20% к цене) — это ещё один независимый слой.

> ⚠️ В копиях лежат личные данные участников (Telegram id, никнеймы, Steam id). Присылай их только в личку владельца или в закрытый чат, куда доступ есть у доверенных людей.

**Восстановление из копии:** скачай файл `bot_….db` из Telegram → `systemctl stop rustbot` → замени `/opt/rustbot/bot.db` этим файлом (переименуй в `bot.db`), удали рядом `bot.db-wal` и `bot.db-shm` → `chown bot:bot /opt/rustbot/bot.db` → `systemctl start rustbot`.

**Проверь копию хотя бы раз:** открой `export_….zip` на компьютере — убедись, что файлы читаются. Копия, которую ни разу не пробовали открыть, — не гарантия.

## 9. Безопасность
- `.env` с токеном и ключом Steam никому не отправляй и не выкладывай в публичный репозиторий (в `.gitignore` он уже есть). Если токен засветился — перевыпусти его в @BotFather (`/revoke`).
- Вход по SSH лучше делать по ключу, а не по паролю (в Termius ключ создаётся в пару кликов).
- Раз в месяц: `apt update && apt upgrade -y`.

## 10. Если что-то не работает
| Симптом | Что проверить |
|---|---|
| Бот молчит | `systemctl status rustbot`, затем `journalctl -u rustbot -n 50` |
| «Conflict: terminated by other getUpdates» | запущена вторая копия бота (на ПК или ещё где-то) |
| Анкеты не приходят в группу | бот не админ группы или нет права писать в топики; неверный ID топика |
| «Привязка Steam не настроена» | нет `STEAM_API_KEY` в `.env` |
| Нет заявок в канале «Поиск команды» | бот не админ канала с правом публикации |
| Время в мероприятиях сдвинуто | проверь `TIMEZONE` в `.env` (по умолчанию Europe/Moscow = МСК) |

## 11. Нагрузка и когда что менять
- Бот использует long polling и SQLite (режим WAL). Это уверенно держит **несколько тысяч участников**: запросы к базе занимают миллисекунды, рассылки идут со скоростью ~20 сообщений в секунду (лимиты Telegram).
- Когда участников станет **десятки тысяч**, стоит перейти на PostgreSQL и webhook — это отдельная доработка, обращайся.
- Состояния форм (анкета в процессе заполнения) хранятся в памяти: после перезапуска бота человеку придётся начать форму заново. На данные в базе это не влияет.
